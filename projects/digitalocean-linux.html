Building Linux Cloud Infrastructure on DigitalOcean

A practical engineering walkthrough covering Ubuntu server administration, Docker containerization, Apache Guacamole, PostgreSQL database connectivity and infrastructure monitoring using Prometheus and Grafana.

By Ambrose Onsare Technical walkthrough Ubuntu 24.04 LTS
DigitalOcean Ubuntu Docker PostgreSQL Guacamole Prometheus Grafana

01. Introduction

Cloud infrastructure is more than provisioning a virtual machine. A production-oriented Linux environment requires system administration, secure remote access, application deployment, database connectivity and continuous monitoring.

In this project, I worked with DigitalOcean to deploy and administer an Ubuntu-based environment. The work involved managing Linux services, troubleshooting SSH authentication, deploying Docker containers and configuring monitoring components.

The environment also provided an opportunity to work with Apache Guacamole for browser-based remote access and PostgreSQL for application and database connectivity.

Project scope: This article documents the practical environment and configurations we worked on. It distinguishes the deployed components from configuration exercises and troubleshooting investigations.

04. Linux Server Administration

Linux command-line administration formed the foundation of the project. I used Ubuntu package management, system utilities and service-management commands to administer the environment.

Updating the operating system

# Refresh package repositories
sudo apt update

# Upgrade installed packages
sudo apt upgrade -y

# Install common utilities
sudo apt install curl wget vim \
  unzip htop net-tools -y

Managing Linux services

# View service status
sudo systemctl status ssh

# Restart a service
sudo systemctl restart ssh

# Enable a service at boot
sudo systemctl enable ssh

# Inspect service logs
sudo journalctl -u ssh

Understanding systemd, service states and journal logs is particularly important when troubleshooting Linux applications and infrastructure services.

05. SSH Configuration and Authentication

SSH was the primary method for administering the cloud server. During the work, we encountered public-key authentication failures when attempting to establish a connection. 

Permission denied (publickey)

Investigating SSH

# Inspect SSH service
sudo systemctl status ssh

# Check listening ports
sudo ss -tulpn

# Validate SSH server configuration
sudo sshd -t

# Inspect authentication logs
sudo journalctl -u ssh

SSH key management

# Generate an ED25519 key pair
ssh-keygen -t ed25519 -C "portfolio-server"

# Inspect the SSH directory
ls -la ~/.ssh

# Set directory permissions
chmod 700 ~/.ssh

# Set authorized keys permissions
chmod 600 ~/.ssh/authorized_keys

SSH private keys must never be shared or uploaded to GitHub. Use sanitized examples and keep authentication secrets outside the public portfolio.

XRDP integration

We also configured an XRDP service for Linux remote desktop sessions. The service was configured to use port 8933 and bind to localhost. 

# Check XRDP status
sudo systemctl status xrdp

# Inspect listening port
sudo ss -tulpn | grep 8933

# Review XRDP logs
sudo journalctl -u xrdp

The important architectural distinction is that XRDP provides the remote desktop endpoint, while Guacamole provides the browser-based access layer.

08. PostgreSQL Database Connectivity

PostgreSQL was involved in two different areas of the work. The first was the PostgreSQL container supporting Guacamole. The second was a separate DigitalOcean managed PostgreSQL database that we accessed from Ubuntu.

Installing the PostgreSQL client

# Install PostgreSQL client tools
sudo apt install postgresql-client -y

# Check client version
psql --version

Connecting to the managed database

# Example connection
psql -h DATABASE_HOST \
  -U DATABASE_USER \
  -d etimsdb \
  -p DATABASE_PORT

The database connection was also used to work with the etimsdb database.

Investigating authentication problems

During connectivity troubleshooting, we encountered: 

fe_sendauth: no password supplied

We investigated password handling and the PostgreSQL password file, including the .pgpass configuration. 

# Create password file
touch ~/.pgpass

# Restrict file permissions
chmod 600 ~/.pgpass

# Edit configuration
nano ~/.pgpass

The password file follows this format: 

hostname:port:database:username:password

A PostgreSQL password file must have appropriate permissions. Never place actual database credentials in public configuration files or Git repositories.

09. Prometheus and Grafana Monitoring

Monitoring was another major part of the infrastructure work. We deployed Prometheus, worked with Node Exporter and configured monitoring targets, including PostgreSQL metrics.

Logical Prometheus and Grafana monitoring architecture.

Prometheus configuration validation

# Validate configuration
promtool check config /etc/prometheus/prometheus.yml

# Check Prometheus status
sudo systemctl status prometheus

# Inspect service logs
sudo journalctl -u prometheus

We encountered YAML parsing issues while configuring Prometheus scrape targets. The configuration was reviewed and corrected during troubleshooting.

Monitoring objectives

  • Collect Linux server resource metrics.
  • Monitor CPU, memory and filesystem utilization.
  • Configure Prometheus scrape targets.
  • Integrate PostgreSQL metrics.
  • Use Grafana to visualize collected monitoring data.

10. Troubleshooting and Lessons Learned

Infrastructure deployments rarely proceed without challenges. The following are some of the issues we investigated during the project.

SSH authentication

We investigated public-key authentication failures, SSH key configuration and file permissions.

PostgreSQL authentication

We encountered missing password errors and investigated the .pgpass configuration and database connection parameters.

Prometheus configuration

YAML parsing errors were investigated while configuring scrape jobs and monitoring targets.

Container administration

Docker Compose, container status, logs and service connectivity were important parts of deployment troubleshooting.

Key technical lessons

  • Validate configuration files before restarting services.
  • Use service logs to identify the source of failures.
  • Keep database credentials and SSH keys secure.
  • Understand the relationship between containers and networks.
  • Monitor resource utilization on small cloud droplets.
  • Separate application databases from external managed databases.
  • Document infrastructure changes and troubleshooting steps.

11. Conclusion

This project provided practical experience with administering Ubuntu cloud infrastructure and deploying services using Docker. It brought together Linux administration, remote access, database connectivity and monitoring into one technical learning environment.

The work also reinforced the importance of troubleshooting, service management, configuration validation and secure infrastructure administration.

These are skills that are useful when managing cloud-hosted applications and modern IT infrastructure.
